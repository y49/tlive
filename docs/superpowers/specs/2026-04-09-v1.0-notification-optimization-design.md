# TLive v1.0 Notification Optimization Design

> Date: 2026-04-09
> Status: Approved
> Goal: Activity-aware notification system with full AskUserQuestion support, zero permission timeout, surpassing happy/hapi/claudecodeui.

## Background

### Current Problems

1. **5-minute permission timeout** — `PendingPermissions` gateway auto-denies after 5min, breaking the core "user away" scenario. All three reference projects use no timeout.
2. **No activity awareness** — IM gets spammed with every event regardless of whether user is at the terminal.
3. **AskUserQuestion not handled** — Questions from Claude can't be answered from IM.
4. **Notification format is flat text** — No tool-specific formatting, no aggregation, no session context.

### Reference Project Comparison

| Capability | happy | hapi | claudecodeui | TLive v1.0 (target) |
|---|---|---|---|---|
| Permission timeout | None | None | `timeoutMs: 0` | **None** |
| Activity detection | 10min session-level | Browser visibility | None | **30s terminal input** |
| Notification suppression | None | Hidden tab only | None | **Full active/away** |
| AskUserQuestion from IM | Via mobile app | Via Mini App buttons | Web UI | **IM text reply + buttons** |
| Tool call aggregation | None | None | None | **Batched summary** |
| Multi-IM | Telegram | Telegram | None | **TG/Discord/Feishu** |

## Architecture

### Core Concept: Activity-Aware Dual Channel

```
User at terminal (active):        User away (inactive > 30s):
  Terminal: full TUI                Terminal: waiting / running
  IM: critical only                 IM: full activity sync
    → permission_request              → all tool calls (aggregated)
    → ask_user_question               → text summaries
    → error                           → permission_request
    → session_complete                 → ask_user_question
                                      → error / session_complete
```

Detection: `lastTerminalInputAt` updated on every PTY stdin write. NotificationHub checks `Date.now() - lastTerminalInputAt > ACTIVE_THRESHOLD` before dispatching info-level notifications.

### Notification Type System

```typescript
/** All notification types with their delivery rules. */
type NotificationKind =
  | 'permission_request'   // Always push. Buttons: Allow/Deny/Takeover
  | 'ask_user_question'    // Always push. Options buttons or text reply
  | 'error'                // Always push
  | 'session_complete'     // Always push
  | 'activity_text'        // Away only. Claude's text response (truncated)
  | 'activity_tool'        // Away only. Tool calls (aggregated)
  ;

interface NotificationRule {
  alwaysPush: boolean;     // true = ignore active state
  aggregate: boolean;      // true = batch multiple events into one message
  maxTextLength: number;   // truncate body beyond this
}

const NOTIFICATION_RULES: Record<NotificationKind, NotificationRule> = {
  permission_request:  { alwaysPush: true,  aggregate: false, maxTextLength: 500 },
  ask_user_question:   { alwaysPush: true,  aggregate: false, maxTextLength: 500 },
  error:               { alwaysPush: true,  aggregate: false, maxTextLength: 300 },
  session_complete:    { alwaysPush: true,  aggregate: false, maxTextLength: 100 },
  activity_text:       { alwaysPush: false, aggregate: false, maxTextLength: 300 },
  activity_tool:       { alwaysPush: false, aggregate: true,  maxTextLength: 500 },
};
```

### AskUserQuestion Flow

```
Claude writes AskUserQuestion tool_use to .jsonl
    ↓
SessionScanner detects tool_use with name='AskUserQuestion'
    ↓ (proactiveQuestionDelay: 5s, skip if tool_result appears)
TLiveLoop.handlePermissionNeeded() — but with question-specific formatting
    ↓
NotificationHub.push() — always push (alwaysPush: true)
    ↓
IPC → Bridge → IM adapters
    ↓
IM displays:
  ❓ Claude asks · myapp · #c7ab
  Which database should we use?
  [PostgreSQL] [SQLite] [MySQL] [Skip]
  — or reply with text —
    ↓
User action:
  A) Clicks button → callback: askq:<toolUseId>:<optionIndex>
  B) Replies with text → interceptReply detects replyToMessageId
  C) Clicks [Skip] → callback: askq:<toolUseId>:skip
    ↓
Bridge → IPC → tlive claude
    ↓
SessionManager: kill PTY → SDK resume → inject answer → restore PTY
```

### Permission Request Flow (No Timeout)

```
Claude writes tool_use to .jsonl (e.g., Bash: rm -rf)
    ↓
SessionScanner detects, starts timer (proactiveNotifyDelay: 60s)
    ↓ (if no tool_result within delay)
NotificationHub: push permission_request (alwaysPush)
    ↓
IM:
  ⚠️ Permission · myapp · #c7ab
  🔧 Bash
  `rm -rf node_modules && npm install`
  [Allow] [Deny] [Takeover]
    ↓ (NO timeout — waits indefinitely)
User clicks [Allow]
    ↓
Bridge → IPC → tlive claude
    ↓
SessionManager: handoff to SDK → resolve permission → restore PTY
```

### Tool Call Aggregation (Away Mode)

When user is away, tool_use events are aggregated before dispatch:

```
Within batch window (250ms default):
  tool_use: Edit src/config.ts
  tool_use: Edit src/loop.ts
  tool_use: Bash `npm test`
    ↓ (batch timer fires)
Single IM message:
  Terminal · myapp · #c7ab
  🔧 Edit src/config.ts
  🔧 Edit src/loop.ts
  🔧 Bash `npm test`
```

### Notification Format Templates

```typescript
const formatTemplates: Record<NotificationKind, (ctx: FormatContext) => string> = {
  permission_request: (ctx) =>
    `⚠️ Permission · ${ctx.sessionTag}\n` +
    `🔧 ${ctx.toolName}\n` +
    formatToolArgs(ctx.toolName, ctx.toolInput),

  ask_user_question: (ctx) =>
    `❓ Claude asks · ${ctx.sessionTag}\n\n` +
    ctx.questionText,

  error: (ctx) =>
    `❌ Error · ${ctx.sessionTag}\n` +
    ctx.text,

  session_complete: (ctx) =>
    `✅ Done · ${ctx.sessionTag}`,

  activity_text: (ctx) =>
    `Terminal · ${ctx.sessionTag}\n` +
    truncate(ctx.text, 300),

  activity_tool: (ctx) =>
    `Terminal · ${ctx.sessionTag}\n` +
    ctx.toolSummaries.map(t => `🔧 ${t}`).join('\n'),
};
```

## Changes Required

### 1. Remove Permission Timeout

**File: `bridge/src/permissions/gateway.ts`**
- Change default timeout from 300000ms (5min) to 0 (no timeout)
- Remove auto-deny on timeout

**File: `bridge/src/main.ts`**
- Remove `onPermissionTimeout` notification ("timed out 5m, denied by default")

**File: `src/sdk/permissionHandler.ts`**
- `ClaudePermissionHandler`: default timeout already configurable, ensure `timeoutMs: 0` for AskUserQuestion

### 2. Activity Awareness

**File: `src/loop.ts`**
- Add `lastTerminalInputAt` tracking (updated in `handleTerminalInput`)
- Add `isUserActive()` method: `Date.now() - lastTerminalInputAt < ACTIVE_THRESHOLD`
- Pass active state to NotificationHub on push

**File: `src/im/notificationHub.ts`**
- Add `isUserActive` callback to constructor options
- `push()` checks: if `!rule.alwaysPush && isUserActive()` → suppress

**File: `src/config.ts`**
- Add `activeThreshold: number` (default 30000ms)

### 3. AskUserQuestion Support

**File: `src/core/sessionScanner.ts`**
- Already detects AskUserQuestion tool_use (shorter delay)
- Extract question text and options from tool input

**File: `src/loop.ts`**
- `handlePermissionNeeded`: detect AskUserQuestion, format with question text + option buttons
- Button callbackData format: `askq:<toolUseId>:<optionIndex>` / `askq:<toolUseId>:skip`

**File: `bridge/src/engine/terminal-relay.ts`**
- `interceptReply`: also handle askq callbacks (new handler in registry)
- Forward `question_answer` IPC message type

**File: `bridge/src/engine/callback-router.ts`**
- Handle `askq:` prefix callbacks for terminal-originated questions

**File: `src/cli/claude.ts`**
- Handle `question_answer` IPC message → write answer to PTY

### 4. Notification Format & Aggregation

**File: `src/sdk/messageNormalizer.ts`**
- Add `FormatContext` interface
- Replace flat `formatForIM` with template-based `formatNotification`
- Add `aggregateToolCalls()` function

**File: `src/im/notificationHub.ts`**
- Aggregate `activity_tool` events within batch window
- Emit aggregated message instead of individual ones

### 5. Notification Rules Engine

**File: `src/im/notificationRules.ts` (new)**
- `NotificationKind` type and `NOTIFICATION_RULES` registry
- `shouldPush(kind, isActive)` — single decision function
- `getRule(kind)` — get formatting/aggregation config

## Success Criteria

1. Permission requests wait indefinitely — no 5-minute auto-deny
2. AskUserQuestion answerable from IM (button click or text reply)
3. User at terminal → IM only gets critical notifications
4. User away → IM gets aggregated activity + all critical
5. Notification format includes session tag, tool-specific args, action buttons
6. All existing tests pass + new tests for notification rules
