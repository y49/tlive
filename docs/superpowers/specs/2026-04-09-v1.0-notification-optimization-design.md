## Category A: Core Notification System (Items 1-6)

### A1. fd3 Thinking Indicator [ref:happy]

PTY spawns claude with fd3 pipe. Parse `fetch-start`/`fetch-end` JSON events to track API call state.

```
fd3 data: { type: 'fetch-start', id: 'xxx', timestamp: ... }
  → thinkingState = true → IM: "🤔 Thinking..."
fd3 data: { type: 'fetch-end', id: 'xxx' }
  → remove from activeFetches
  → 500ms debounce → if activeFetches.size === 0 → thinkingState = false
```

**Files:** `src/core/ptyManager.ts` (fd3 pipe support), `src/core/thinkingTracker.ts` (new)

**Note:** node-pty doesn't support fd3 directly. Use `child_process.spawn` with `stdio: ['pipe','pipe','pipe','pipe']` for fd3, pipe fd0-2 through node-pty for terminal emulation. If too complex, fallback to scanner-based detection (tool_use without tool_result = likely thinking).

### A2. IPC Auto-Reconnect [ref:happy]

`IPCClient` reconnects with exponential backoff when bridge restarts.

```typescript
// Already implemented in src/ipc.ts — enhance with:

```

**Files:** `src/ipc.ts`

### A3. Remove Permission Timeout

```
Current: PendingPermissions auto-denies after 5 minutes
Target:  timeoutMs: 0 for all IM-routed permissions (wait indefinitely)
```

**Files:**

### A4. AskUserQuestion Full Support

Scanner detects `AskUserQuestion` tool_use → extract question text + options → push to IM.

```
IM display:
  ❓ Claude asks · myapp · #c7ab
  Which database should we use?
  [PostgreSQL] [SQLite] [MySQL] [Skip]
  — or reply with text —

User clicks [PostgreSQL]:
  → IPC: question_answer { toolUseId, answer: 'PostgreSQL' }
  → SessionManager: kill PTY → SDK resume → inject answer → restore PTY

User replies text "用 Redis":
  → interceptReply detects replyToMessageId
  → IPC: question_answer { toolUseId, answer: '用 Redis' }
```

**Files:**
- `src/core/sessionScanner.ts` — extract question text/options from AskUserQuestion input
- `src/loop.ts` — format question notification with option buttons
- `bridge/src/engine/terminal-relay.ts` — handle `askq:` callbacks + text reply
- `src/cli/claude.ts` — handle `question_answer` IPC message

### A5. Activity-Aware Notification

```
Active (terminal input within 30s):
  Push: permission_request, ask_user_question, error, session_complete
  Suppress: activity_text, activity_tool

Away (no input > 30s):
  Push: everything (tool calls aggregated)

Always push:
  permission_request, ask_user_question, error, session_complete
```

**Files:**
- `src/loop.ts` — `lastTerminalInputAt` tracking, `isUserActive()` method
- `src/im/notificationRules.ts` (new) — rules registry with `shouldPush(kind, isActive)`
- `src/im/notificationHub.ts` — accept `isUserActive` callback, filter on push
- `src/config.ts` — `activeThreshold` (default 30000ms)

### A6. Tool Call Aggregation

Away mode batches tool_use events into a single message:

```
Within batch window (250ms):
  tool_use: Edit src/config.ts
  tool_use: Edit src/loop.ts  
  tool_use: Bash `npm test`
    ↓
Single IM message:
  Terminal · myapp · #c7ab
  🔧 Edit src/config.ts
  🔧 Edit src/loop.ts
  🔧 Bash `npm test`
```

**Files:** `src/im/notificationHub.ts` — aggregate `activity_tool` events within batch, emit combined

## Category B: Competitive Features (Items 7-11)

### B7. Effort/Model IM Switching [ref:hapi]

IM control panel buttons to change effort and model mid-session, without restart.

```
Menu → Session Settings:
  Effort: [low] [medium] [high] [max]
  Model:  [Sonnet] [Opus] [Haiku] [Auto]
```

Implementation: Bridge already has effort/model per-chat state (`SessionStateManager`). New: forward setting changes via IPC to terminal process. Terminal updates env vars or SDK options for next interaction.

**Files:**
- `bridge/src/engine/terminal-relay.ts` — handle `config_update` IPC message
- `src/cli/claude.ts` — receive config updates, store for next SDK handoff

### B8. Git Worktree Isolation [ref:happy, hapi]

`tlive claude --worktree` creates an isolated git worktree for the session.

```bash
tlive claude --worktree           # auto-name: tlive-c7ab
tlive claude --worktree my-feat   # named: tlive-my-feat
```

Implementation:
```
git worktree add ../{repo}-worktrees/tlive-{name} -b tlive/{name}
  → spawn claude in worktree dir
  → on session end: prompt cleanup or keep
```

**Files:** `src/core/worktreeManager.ts` (new), `src/cli/claude.ts` — `--worktree` flag

### B9. Session List/Switch/Resume

IM and CLI both can manage sessions:

```
IM Menu → Sessions:
  #c7ab myapp · active · 5 min ago
  #a1b2 blog · paused · 2 hours ago
  [Switch] [Resume] [Stop]

CLI:
  tlive sessions              # list
  tlive claude --resume       # resume last
  tlive claude --resume a1b2  # resume specific
```

Implementation: `ProjectRegistry` already tracks projects. Extend with session metadata (state, lastActivity, messageCount). Scanner reads existing .jsonl files on startup to populate.

**Files:**
- `src/core/sessionDiscovery.ts` — enhance `findLastSession` → `listSessions()` with metadata
- `src/loop.ts` — expose session list via IPC
- `bridge/src/engine/terminal-relay.ts` — handle `session_list` request/response

### B10. Cost/Token Tracking [ref:happy]

Parse token usage from Claude's .jsonl (assistant messages contain `usage` field).

```json
{ "type": "assistant", "message": { "usage": { "input_tokens": 1500, "output_tokens": 300, "cache_creation_input_tokens": 0, "cache_read_input_tokens": 800 } } }
```

Accumulate per-session. Display in IM on request or at session end:

```
✅ Done · myapp · #c7ab
Tokens: 15.2k in / 3.1k out / 2.8k cached
Cost: ~$0.12
```

**Files:**
- `src/core/costTracker.ts` (new) — accumulate from scanner events
- `src/loop.ts` — include cost in session_complete notification
- Pricing table: hardcoded per-model rates (update periodically)

## Category C: Polish (Items 12-14)

### C12. Error Classification [ref:happy]

Distinguish error types for appropriate handling:

```typescript
class TLiveError extends Error {
  constructor(message: string, public code: ErrorCode) { super(message); }
}

type ErrorCode =
  | 'ABORT'           // User-initiated, ignore gracefully
  | 'PTY_EXIT'        // Process exited with code, propagate
  | 'IPC_DISCONNECT'  // Temporary, auto-reconnect
  | 'SDK_ERROR'       // SDK threw, notify IM
  | 'SCANNER_ERROR'   // File read failed, retry
  ;
```

**Files:** `src/core/errors.ts` (new), update catch blocks across codebase

### C13. Graduated Permission Modes [ref:hapi]

4 modes configurable from IM, controlling SDK `canCallTool` behavior:

```
default      → prompt for each tool (current)
accept-edits → auto-allow Read/Edit/Write/Glob/Grep, prompt for Bash/Agent
auto-approve → auto-allow everything except dangerous (rm -rf, git push --force)
yolo         → allow all, no prompts
```

IM buttons:
```
🔐 Permission Mode
[Default] [Accept Edits] [Auto-Approve] [Yolo]
```

**Files:**
- `src/sdk/permissionHandler.ts` — add mode-based `isAllowed()` logic
- `src/sdk/permissionPolicies.ts` (new) — policy registry per mode
- `bridge/src/engine/terminal-relay.ts` — forward mode changes via IPC

### C14. QR Code Terminal Pairing [ref:happy]

First-time IM setup: terminal displays QR code → user scans in IM → auto-configures chatId.

```
tlive setup --qr
  → generate one-time token
  → display QR in terminal (text-based QR using qrcode-terminal)
  → encode: tlive://pair?token=xxx&host=192.168.1.5:8849
  → IM bot: /start with deep link → auto-pair
```

**Files:** `src/cli/setup.ts` (new), `bridge/src/engine/terminal-relay.ts` — handle pairing flow

## Notification Type System (Updated)

```typescript
type NotificationKind =
  // Always push
  | 'permission_request'    // ⚠️ Tool approval with buttons
  | 'ask_user_question'     // ❓ Question with options/text reply
  | 'error'                 // ❌ Runtime error
  | 'session_complete'      // ✅ Done with cost summary
  | 'todo_update'           // 📋 Task list changed
  | 'thinking'              // 🤔 Claude is thinking (toggle, not batched)
  // Away-only push
  | 'activity_text'         // 💬 Claude's text response (truncated)
  | 'activity_tool'         // 🔧 Tool calls (aggregated)
  ;

const RULES: Record<NotificationKind, { alwaysPush: boolean; aggregate: boolean }> = {
  permission_request:  { alwaysPush: true,  aggregate: false },
  ask_user_question:   { alwaysPush: true,  aggregate: false },
  error:               { alwaysPush: true,  aggregate: false },
  session_complete:    { alwaysPush: true,  aggregate: false },
  todo_update:         { alwaysPush: true,  aggregate: false },
  thinking:            { alwaysPush: true,  aggregate: false },
  activity_text:       { alwaysPush: false, aggregate: false },
  activity_tool:       { alwaysPush: false, aggregate: true  },
};
```
