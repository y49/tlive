这条 HUD 渲染细节

  • Header line — model + workspace + git branch
  • Progress bars — Context / Cost / 也可加 Token-quota,用 unicode block char 做条
  • Cache — 🔥 N min(剩余 cache 时间)
  • Current activity — ◐ {tool} · {elapsed}(thinking 时显示 "◐ thinking · 0.2s")
  • Tool tally — ✓ Bash ×3 | ✓ Read ×2 (本 session 累计)
  • Subagent line(可选) — ✓ general-purpose [sonnet]: Polish — ...
  • Footer — session id (短) + idle time + turn 计数

所有这些都是 1 条消息的多行内容。每个事件触发一次 adapter.edit,内容整体重 build。

edit-in-place 稳定性方案

claude-hud 的 statusline 在 terminal 里 reliable 因为是直接重绘。Telegram edit 不可靠 → 解法:

  • 节流 — 每个事件不立即 edit,debounce 到 ≥500ms,合并 burst
  • 幂等内容 — text 没变(同 hash)就不发 edit
  • fallback 策略 — edit 失败 → 不重发(避免双消息),记 stderr,等下次更新自然修复
  • send-only fallback — 如果 30s 内 edit 失败 ≥3 次,降级为 send-new + delete-old(最坏 case 也只 1 条可见)
