方案 D — Per-turn HUD(我的最终倾向)

每个 turn 开始时发一条 HUD 消息,turn 进行中只 edit 这一条,turn 结束它就停在那变成"这轮的记录"。下一 turn 开始时发新 HUD。Telegram + 飞书 都用 native edit,无 pin / 无删除。

为什么 per-turn 比 pinned 更好(双平台 + 你的约束下)

  • 无删除/撤回 — 历史 turn 的 HUD 自然停留,不动它
  • 飞书友好 — 不需要 pin 权限,只用普通 message edit / card update
  • Telegram 友好 — 普通 message + edit_message_text(常用、稳定)
  • 每 turn 一份记录 — 可滚动看历史,知道每轮花了多少 / 用了哪些 tool
  • edit 范围窄 — 只在 turn 内 edit(几秒到几分钟),turn 结束就 freeze,不会出现"5 小时后还在 edit 一个老消息"导致 Telegram 拒绝的边界

实现细节(关键点)

  • 1 turn = 2 消息:HUD(edit-in-place)+ reply(send-only)
  • HUD 内容 build pipeline:turn_start 初始化 → tool_use_start/result 增量 edit → turn_end 最终 edit(写入 cost / 总耗时 / cache 状态)
  • edit 节流:每个事件 schedule edit,debounce 500ms 合并,内容 hash 不变就不发
  • edit 失败 fallback:不重发(避免双消息),只 stderr 记 reason,等下个事件自然修复
  • 飞书 card:用 lark interactive card,update_card API 等价于 edit
  • permission card 仍独立(不在 HUD 内,因为有 button 交互)
  • reaction 仍在用户消息上(👀 → 🤔 → 👌 / 💔)
  • attachment 独立消息(Write 输出文件时)
